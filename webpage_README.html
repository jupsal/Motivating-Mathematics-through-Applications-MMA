MMA structure

The MMA webpage is created in quarto markdown. The quarto markdown documentation is extensive. You should view the Websites section. Quarto markdown (qmd) mostly matches Markdown syntax, which is very intuitive and easy to write. Quarto’s markdown basics will help you get started with markdown if you are new to it. Most of the LaTeX that you are used to works here. I edit my qmd files in VS Code.

This webpage is split into two main trees, both of which link to the other side.

  • Application topic: These form a tree: Chemistry > Reaction equations > Kinetics.
  • Math topic: an area of math, e.g. Logarithms or Differential equations.

The webpage is created through a series of .qmd files in a file directory. Several terms will be used in this document. They are defined below.

Terms

  • Hub: a page that introduces a topic and lists relevant pages. A hub has a short background and an automatic list (see listing) of connected pages (e.g., sub applications or associated mathematics). A hub has no or worksheets of its own. Those are in conections. Each application topic and each math topic has a hub, e.g. the Chemical Kinetics hub or the Logarithms hub. Hubs should not need much editing, since they are automatically built with listings (see below).
  • Connection: a page about one application topic used with one math topic, e.g. Chemical Kinetics & Differential equations. This is the core of MMA. Connection pages are the main page users will access, usually through a “filter chip”. A connection page has, in order:
    • Background: an explanation of the application and how the math applies, written for instructors, but easy for instructors to copy if they want to share background information with students. The background should be written in three ways so instructors can easily share the level of detail they want to share with students.
      • Minimum: a paragraph you could put on a homework assignment or worksheet.
      • Medium: a longer explanation, e.g., something that could be discussed verbally in class in 5 minutes.
      • Extended: a deep dive, with references. This is mostly used for instructors or those wishing to learn more about the topic.
    • Prerequisite: material students should know before starting a connection or resource. Link it to the page that covers it, if there is one.
    • Learning outcome: what students can do after a connection or resource, written with a measurable verb (“Convert…”, “Interpret…”, not “Understand…”). See REVISED Bloom’s Taxonomy Action Verbs
      • TODO: should these be here, or in the resources, or both? It would be nice to have these on the page as clickable resources. Maybe we make a listing for these?
  • Resource: something instructors can use in class that belongs to one connection: a lesson, worksheet, problem set, etc. Each resource is its own page, kept in the resources/ folder of its connection.
    • Learning outcome: what students can do after a connection or resource, written with a measurable verb (“Convert…”, “Interpret…”, not “Understand…”). See REVISED Bloom’s Taxonomy Action Verbs
  • Tag: a label in a page’s categories: list (see Page YAML headers), e.g. categories: [Kinetics, Logarithms]. Tags are how a page shows up on math topic hubs (using listings, see below). A tag must match the hub’s title exactly: “Logarithm” will not match “Logarithms”.
  • Listing: an automatic list of pages, built by Quarto every time the site is rendered. Hubs use listings, so they are automatically updated when a new connection is added.

Webpage structure

Every viewable page (Hub, Connection, or Resource) is the index.qmd file inside its own folder, so the folders below match the pages of the website. For example:

  • Homepage: index.qmd
    • Application topics: applications/
      • Chemistry (hub): chemistry/
        • Reaction equations (hub): reaction-equations/
          • Chemical Kinetics (hub): kinetics/
            • Chemical Kinetics & Differential equations (connection): odes/
              • Resources (lessons, worksheets, …): resources/*.qmd
            • Chemical Kinetics & Logarithms (connection): logarithms/
              • Resources (lessons, worksheets, …): resources/*.qmd
          • Stoichiometry (hub): stoichiometry/
        • Titration (hub): titration/
    • Math topics: math/
      • Logarithms (hub): logarithms/
      • Differential equations (hub): differential-equations/

Site-wide files

These files apply to the whole site, defining site structure and style. Most contributors won’t need to edit them, but you may want to experiment with changes on your own GitHub branch.

Files and folders whose names start with _ are not turned into pages and may not be visible to you when you pull from GitHub.

  • _quarto.yml: the site’s settings: the site title, the navigation bar at the top of every page, the theme, and defaults for every page (for example, a table of contents on every page toc: true). A setting in a page’s own YAML header overrides the default here for that page. Changes here affect every page; edits must be approved by the site administrator (Jeremy).
  • styles.css: custom styling (colors, spacing, fonts) added on top of the theme. This is not in use right now, but may be something you want to edit if you want specific styles.
  • _templates/: starter files for new hub, connection and resource pages.
  • _site/: the built website, created by quarto render. Don’t edit anything here; it is replaced every time the site is built.
  • .quarto/: Quarto’s internal working files, created automatically when the site is rendered. Don’t edit it. It is safe to delete because Quarto rebuilds it with each rendering.
  • .gitignore: a file telling GitHub which files/folders to ignore when pushing to the repository.

How pages work

Each page is a .qmd file consisting of a YAML header (delineated with ---), containing the page settings, followed by the page’s text. The page text is written in markdown and should be relatively straightforward. The header anatomy is described below.

Page YAML headers

Each page begins with a YAML header, enclosed with ---. Here is an example, from the Chemical Kinetics page.

---
title: "Chemical Kinetics"
description: "Modeling reactant concentrations as functions time."
categories: [Chemistry, Reaction equations]
listing:
  id: connections
  contents: "./*/index.qmd"
  type: table
  fields: [title, description, categories]
  sort: title
---

The following table describes what different header settings do, how to use them, and when you might want to use them.

  • title: The page’s heading and the name in the browser tab. When this page appears in a list on another page (e.g., through a listing), this is the link text.
  • description: A summary shown under the title. When this page appears in a list on another page, this is the text beside the link. Ideally this should be one sentence and certainly no more than two sentences.
  • categories: A list of the page’s tags. They appear as small labels under the page title. Categories are used for searching and organization. See quarto’s description.
  • listing: This creates a “listing” (see Section 1.1), an automatic list of other pages on the site matching specifications defined below. This needs to be edited to define the contents and look of the listing. Multiple listings can exist on one page, creating two searchable tables.
    • id: connections: The list’s name (connections). It tells Quarto where to put the list on the page (see #page-body). This is arbitrary, you decide it.
    • contents: Which pages to list. ./*/index.qmd means “all files named index.qmd in the next-level of subdirectories.” Each connection page will displayed in its own row.
    • type: table: Show the list as a table. Other options: default (a list with summaries) and grid (cards).
    • fields: [title, description, categories]: The columns of the listing table. These come from the listed page’s own header. These are searchable in the listing.
    • sort: title: Order the rows alphabetically by title. See Quarto documentation for other options.
  • toc: false: toc means “table of contents”. By default, toc is true which creates a table of contents in the rigth margin. For short pages, you may have toc: false.

Page body

The page body depends on whether the page is a Hub, Connection, or Resource.

Page listing

The listing, defined in the header, should be placed at the bottom of the page. To show it on the webpage, put an empty block with the list’s id in the page text, where the list should appear:

## Math connections

::: {#connections}
:::
Note

::: creates a “fence” in qmd. Fences are used to create HTML <div> or <span> elements. See the pandoc user guide for more. You will often see / use them to create special elements.

Without this block, Quarto automatically puts the list at the end of the page without a header.

Contributing to the MMA website with GitHub

The instructions below are for developers who plan to submit several pages to MMA. You should use GitHub if that applies to you. If you plan to contribute only a few times, see the contribute to MMA page.

The website’s source files are kept in a GitHub repository. You can contribute by downloading the source code, making changes on your own computer, and then sending them to GitHub as a pull request. Once the maintainer (Jeremy) approves it, GitHub rebuilds and publishes the website automatically.

Set up (once)

If you have GitHub set up, continue on to step 4 below. If you are new to GitHub, open the note below and get started with GitHub!

NoteSetup GitHub

  1. Create a free account at https://github.com and send Jeremy your GitHub username. You will get an email invitation to the repository.

  2. Install some software:

    • Git: https://git-scm.com/downloads
    • Quarto: https://quarto.org/docs/get-started/
    • (optional, but you need a way to edit .qmd files) VS Code: https://code.visualstudio.com, plus its Quarto extension

  3. Setup Git on your computer Open a terminal. You can do this using “terminal” in MacOS, Windows Powershell, or in VS Code. Run the following commands with the email address of your GitHub account:

    git config --global user.name "Your Name"
git config --global user.email "you@example.com"

  1. Download the project to your computer In the terminal, go to the folder where you want to keep the source code and run:

    git clone https://github.com/<maintainer-github-name>/mma.git

    This creates a folder named mma with all the files. Open that folder in an editor such as VS Code.

Making changes

Run these in the VS Code terminal, inside the mma folder.

  1. Get the latest version:

    git switch main
git pull

  2. Start a branch for your changes. A branch is your own working copy of the source code. It allows you to make changes without worrying about messing up the published version of the source code. You should name the branch after what you are working on. For example,

    git switch -c add-titration-background

    This switches your branch to a branch called “add-titration-background”.

  3. Edit the .qmd files (see Section 2.1). To see your changes in a browser as you work, type the following in the command line in the main MMA folder.

    quarto preview

  4. Save your changes and send them to GitHub:

    git add .
git commit -m "A short description of what you changed"
git push -u origin add-titration-background

    The first time you push, a browser window asks you to sign in to GitHub to confirm your identity.

  5. Open a pull request. Go to the repository page on GitHub. A yellow bar shows your branch with a Compare & pull request button. Click it, describe your change, and click Create pull request.

Jeremy will review the pull request and consider if it is ready to publish or if changes need to be made. If changes need to be made, make the changes and complete step 4 again (git push). If changes are approved, the website will be updated automatically.

By default you cannot push directly to main - that’s where the published website is!
